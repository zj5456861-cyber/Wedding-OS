# Wedding OS · W5 豆包 AI 婚前助手规划（架构预留）

> 本文档仅为 W5 规划与架构预留。当前（W4）不接入任何 AI 模型、
> 不调用豆包 API、不开发聊天功能、不创建 AI 账号系统。

## 1. 产品定位

从「婚前推进管理工具」升级为「有提醒的推进工具」后，AI 助手的角色是**只读分析 + 建议**，
不做自动执行。

### AI 默认权限（只读分析）

禁止 AI 自动执行以下操作：

- 自动删除数据
- 自动修改预算
- 自动修改时间轴
- 自动完成事项

所有写操作遵循固定流程：

```
AI 建议 → 用户确认 → 现有业务接口执行
```

## 2. 数据接入（AI Context Service）

未来 AI 不直接访问数据库。统一通过只读聚合服务读取上下文，
数据全部经现有 RLS（当前登录用户视角）获取。

实现位置：`src/lib/aiContext.ts`（W5 可整体迁移到 Edge Function 复用）。

### 上下文内容

| 模块 | 内容 |
| --- | --- |
| 空间信息 | 空间名称、当前阶段、创建时间 |
| 时间轴 | 总数、已过节点、待办节点、未来节点（含提醒日） |
| 事项 | 总数、未开始/进行中/待线下决定/已完成、带提醒事项 |
| 预算 | 各分类预算/已支出/剩余、总额/已支出/剩余 |
| 支出统计 | 最近 5 笔支出、各分类支出占比 |

## 3. W5 第一阶段功能

1. **当前状态总结**
   例：“距离收房还有 xx 天，目前有 xx 件待处理事项，预算剩余 ¥xx。”

2. **下一步建议**
   基于 时间轴 + 事项 + 提醒 生成建议（例如按提醒日期排序给出“该处理 xx”）。

3. **自动生成事项**
   用户输入“准备订婚” → AI 生成事项列表 → **用户逐条确认后**才写入 tasks。

4. **风险提醒**
   例：装修周期过短、旅行准备不足、预算超支风险（对比分类额度与已支出）。

5. **周/月总结**
   按周/月汇总新增事项、完成事项、支出变化与节点进展。

## 4. 技术预留与未来接入

- 前端入口：首页右下角悬浮按钮（当前点击仅提示“AI助手即将上线”）
- 数据层：`fetchAiContext()` 只读聚合，W5 直接复用或迁至 Edge Function
- 模型接入：豆包 API Key 未来放服务端（Edge Function / 环境变量），不进入前端
- 聊天形态：W5 一期为单轮/简单问答式输入框（另行设计），不做复杂对话系统

## 5. 明确不做（保持边界）

- 当前阶段不开发：AI 聊天页、AI API 调用、AI 账号系统、AI 自动执行
- 附件/AI 复合资料问答：未来版本再评估
